## 1. Резюме Проблеми та Рішення (Контекст)

Ми обговорювали створення **інтерактивного сканера файлів**, який дозволяє користувачеві перебирати ID файлів у URL, обходити захист **Cloudflare** та витягувати назви файлів із заголовків HTTP (`Content-Disposition`).

| Елемент | Проблема/Висновок | Вирішення |
| :--- | :--- | :--- |
| **Ціль** | Отримати назву файлу (заголовки `HEAD`) шляхом перебору `id=[number]` у URL. | Використання **`cloudscraper`** для імітації браузера. |
| **Блокування** | Стандартний `curl` блокується Cloudflare навіть із повними куками, вимагаючи обходу **JavaScript Challenge**. | Використання **`cloudscraper`** для автоматичного проходження JS-перевірок. |
| **Обхід 403** | Необхідно уникати DoS-подібної поведінки та гарантувати відновлення сесії Cloudflare. | **Інтерактивна логіка**: при 403 користувач вручну обирає опцію **'t' (try/обхід)**, що призводить до **створення нового екземпляра скрепера**, який примусово ініціює нову перевірку Cloudflare. |
| **Керування** | Потрібен простий, швидкий та **односимвольний** ввід команд. | Використання **`msvcrt.getch`** (або аналогів) для негайного зчитування символів без натискання Enter (поведінка `choice`). |
| **Структура** | Для легкості змін та контролю процесу потрібна модульна структура. | Розбиття коду на 6 логічних файлів. |

## 2. Фінальна Модульна Структура Коду

Фінальна версія коду (яку ми назвали `file_scanner_v4`) була розбита на 6 файлів для максимальної модульності та контролю.

| Файл | Призначення | Ключові Функції/Класи | Точки Контролю |
| :--- | :--- | :--- | :--- |
| **`main.py`** | Точка входу. Запускає парсинг аргументів та основний цикл. | `main()` | Запуск програми. |
| **`config.py`** | **Конфігурація**. Налаштування, які можуть змінюватися: шляхи, параметри `cloudscraper`, мапінг команд. | `DOWNLOAD_DIR`, `SCRAPER_PARAMS`, `ACTIONS` | Швидка зміна логіки керування (клавіші, шаблони URL). |
| **`session_manager.py`** | **Керування сесією**. Обгортка над `cloudscraper`. | `FileScannerSession`, `renew_session()`, `check_url_head()`, `download_file()` | **Керування обходом 403**: логіка створення **нового екземпляра скрепера** при необхідності. |
| **`io_handler.py`** | **Ввід/Вивід**. Керування відображенням повідомлень та інтерактивним вводом. | `get_action_from_user()`, `handle_403_prompt()` | **Негайний ввід символу** (`msvcrt.getch`) та коректне відображення 403 (перезапис рядка). |
| **`scanner_loop.py`** | **Головний цикл**. Основна логіка перебору ID, обробки статус-кодів та взаємодії між модулями. | `run_scanner_loop()` | Ядро програми: переходи між ID, виклик обробників 403. |
| **`history.py`** | **Внутрішній контроль**. Зберігання історії оброблених посилань. | `ScannerHistory`, `add_success()`, `get_last_successful()` | Точка для розширення логіки звітності чи збереження сесії. |

## 3. Логіка Обходу Cloudflare (Важлива Точка)

Найважливіший момент, який потрібно зберегти:

1.  Якщо отримано **403 Forbidden**, скрипт зупиняє перебір і пропонує:
    * `c/r`: змінити ID (перейти далі/назад)
    * `s/q`: вийти
    * `t/т`: **Створити новий Scraper (Обхід)**.
2.  При виборі **`t`**:
    * `session_manager.renew_session()` викликає **`cloudscraper.create_scraper()`** заново.
    * Новий екземпляр скрепера одразу ж перевіряється на тому самому проблемному URL (`current_id`).
    * Якщо обхід успішний, новий скрепер замінює старий, і головний цикл **повторює перевірку того ж ID** (`continue`).

Ця структура повністю реалізує інтерактивний сканер з надійною логікою обходу Cloudflare, яка контролюється користувачем.
